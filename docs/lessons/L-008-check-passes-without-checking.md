# L-008 검사 스크립트가 결함이 있어도 통과함 (일부만 보거나 비어서 통과)
- 날짜: 2026-11-16
- 키워드: check script, false negative, vacuous pass, mutation, regex, grep, head -1, bash -c, backtick, 검사 허점, 비어서 통과, 변형 검사, 일관성 검사
- 증상: 새로 만든 검사(`scripts/check-workflows.sh`, `scripts/check-spec-consistency.sh`)가 결함이 있는 입력에서도 "통과"했고, 같은 유형의 허점을 CodeRabbit과 독립 검증이 PR마다 반복해서 짚음 (PR #10, #11, #12, 약 10건).
  - 두 패턴 중 하나만 맞아도 통과: `^on:|^  pull_request:`는 `pull_request`를 `push`로 바꿔도 통과.
  - 일부만 확인: `head -1`은 첫 번째 일치만 봐서 뒤에 질문 단계를 추가해도 통과. `draft.*saved`는 주 경로에도 일치해서 직접 경로를 지워도 통과.
  - 추출이 비어서 통과: 상태 이름을 뽑는 정규식이 아무것도 뽑지 못한 채 "모두 정의됨"으로 통과. 밑줄 없는 이름(`archived`)도 놓침.
  - 값 전체를 안 봄: `eas-version`을 정규식으로 부분 확인해 따옴표 값은 거부하고 `27.10.0 || >=27.10.1` 같은 범위는 통과.
  - 주석으로 우회: 주석 줄에만 문구가 있어도 통과.
  - 한 곳만 확인: 같은 문구가 두 곳에 있는데 한쪽만 지워도 통과. 단어 하나(`asks none`→`asks one`)가 바뀌어도 통과.
  - 도구 오류: 문서 본문의 백틱이 `bash -c` 문자열에서 명령으로 해석되어 멀쩡한 문서가 실패.
- 원인: 검사를 "현재 정상 파일이 통과하는지"로만 확인하고 끝냈음. 검사는 결함을 잡아야 존재 이유가 있는데, 결함이 있는 입력에서 실제로 실패하는지는 확인하지 않았음. 또 정규식으로 일부만 보면 통과 조건이 넓어지고, 추출 결과가 비어도 실패로 취급하지 않았음.
- 해결: 각 지적마다 결함을 넣은 문서·워크플로 사본으로 "놓치는 것"을 먼저 재현한 뒤, 값 전체(또는 문장 전체)를 비교하고 추출 개수 가드를 넣고 주석 줄을 제외하고 `bash -c` 대신 직접 비교하도록 고침 (PR #10 `f8dc497`, `df1ac2a`, PR #11 `f1a118e`, PR #12 `b363434`, `9fc904a`).
- 재발 방지:
  - L2: `/lunea-finish` 1단계에 "검사 스크립트를 새로 만들거나 고쳤다면, 결함을 넣은 사본에서 실제로 실패하는지 먼저 확인하고 그 사례를 PR에 적는다" 단계를 추가.
  - 작성 규칙: 값이나 문장은 일부가 아니라 전체를 비교한다. 추출은 최소 개수 가드를 둔다. 검사 대상 텍스트를 `bash -c` 문자열에 넣지 않는다. 하나라도 결함 사본이 통과하면 검사가 아직 끝난 것이 아니다.
  - L3(목표): 이번에 쓴 결함 사본을 회귀 테스트로 저장해 CI에서 "검사가 결함을 잡는지"를 자동으로 확인. 제품 책임자 결정 필요 (작은 후속 작업).
- 방어 수준: 현재 L2 → 목표 L3
