# 고민의 흔적을 남기는 기록 체계 설계
- 날짜: 2026-11-12 / 관련: docs/journal, docs/lessons, .claude/settings.json

## 배경
결정 과정을 포트폴리오·기술 명세에 쓰고 싶고, 동시에 AI가 실수했을 때 과거 해결법을 먼저 참고하게 하고 싶었다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 모든 PR마다 자동으로 기록 생성 | 빠짐 없음 | 잡음이 쌓여 가치 하락, 사실 오류 위험 |
| 필요할 때만 수동 작성 | 품질 높음 | 잊기 쉬움 |
| **의미 있는 순간에 트리거 + 사람 확인** | 품질과 누락 방지의 균형 | 트리거 설계 필요 |

## 결정과 이유
목적별로 세 갈래로 나눴다: 공식 결정은 `docs/adr/`, 이야기형 결정 과정은 `docs/journal/`, 실수와 재발 방지는 `docs/lessons/`. 교훈마다 방어 수준(L0 문서 → L1 CLAUDE.md → L2 스킬 → L3 자동 검사)을 기록하고, 같은 실수가 반복되면 한 단계 올린다. 업계의 ADR, 비난 없는 포스트모템, 그리고 "모든 실수를 영구 규칙으로" 바꾸는 복리형 엔지니어링(compound engineering) 관행을 참고했다.

트리거: `/lunea-log`(직접), `/lunea-finish`(작업 마무리 질문), 리뷰 지적·CI 실패(교훈 초안), 세션 시작 훅(교훈 색인을 맥락에 주입), CodeRabbit 규칙(ADR 상태 변경 PR에 저널 누락 시 지적).

## 결과
이 저널 6편과 교훈 5건을 소급 작성. `.claude/settings.json`에 SessionStart 훅.
