# 기획 핸드오프 검토와 저장소 초기 설정
- 날짜: 2026-11-08 / 관련: PR #1, L-001

## 배경
Lunéa 기획은 19개 파일의 핸드오프 패키지(제품 브리프, PRD, UX, 기술 아키텍처, AI 안전, 백로그, 미결정 사항)로 정리되어 있었다. 문서는 Accepted(확정)·Proposed(기본값)·TBD(반드시 질문) 상태 규칙을 갖고, Claude Code를 주 개발자, 사람을 최종 승인자로 정의했다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 문서를 바로 코드로 옮기며 시작 | 빠름 | TBD 항목을 임의로 확정할 위험 |
| **먼저 검토 보고(Phase 1) 후 승인받고 저장소 생성** | 불일치·누락을 초기에 발견 | 한 단계 더 걸림 |

## 결정과 이유
핸드오프 프롬프트의 Phase 1을 그대로 따랐다. 검토에서 상태명 불일치(`user_review` vs `user_reviewed`), 소프트 삭제와 "삭제 완료" 약속의 충돌, 원문 보존과 기록 수정의 관계 미정, 확인 질문 흐름의 데이터 모델 부재, 근거 검증 기준 부재를 찾았다. 이 항목들은 DOC-01로 남겼다.

저장소는 비공개로, `main`에는 원본 문서만 두고 설정 파일·템플릿·CI는 짧은 브랜치(`chore/bootstrap-repository`)의 첫 PR로 분리했다. CI에는 읽기 전용 권한과 `.env` 커밋 차단 검사를 넣었다.

## 진행 중 생긴 문제와 대응
클라우드 세션에서는 저장소 생성과 브랜치 보호 API가 거부되었다(L-001). 성공을 주장하지 않고, 사람이 빈 저장소를 만든 뒤 세션에 연결해 push·PR을 진행했다. 보호 규칙은 사람이 설정하도록 안내했다.

## 결과
PR #1 merge. CI `baseline` 통과. 이후 모든 작업이 PR 단위로 진행되는 기반이 마련됨.
