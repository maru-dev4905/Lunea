# AI 없이 저장하기(JRN-02): 메모리 저장소와 한 번의 저장 피드백
- 날짜 / 관련: 2026-11-19, LUN-21, ADR-0003, D-14, D-30, D-31, D-32, D-36

## 배경
저장 버튼은 안내 문구만 보여 주었다. LUN-21은 AI·감정·영속 저장 없이 "저장 → Collection·상세에서 다시 읽기"만 연결한다. 일반 저장에 감정 직접 추가 단계를 둘지는 제품 책임자가 2026-11-19에 "입력 없음"으로 정했다(`docs/03a`의 TBD는 별도로 정정 중).

## 고려한 선택지
| 선택지 | 장점 | 단점 | 비용 |
|---|---|---|---|
| 기록 저장소: 기존 `DraftProvider`와 같은 React Context(`RecordsProvider`) | ADR-0003과 일치, 의존성 없음 | 앱을 끄면 사라짐 | 작음 |
| 기록 저장소: 상태 라이브러리 / 기기 저장 | 새로고침 후에도 유지 | ADR-0003 범위 밖, 데이터 모델·삭제(D-30) 설계 필요 | 큼 |
| 저장 직후: 상세로 이동(`replace`) | 저장된 것을 바로 확인, 뒤로 가면 Today | 상세가 저장 전용 화면처럼 보일 수 있음 | 작음 |
| 저장 직후: 저장 전용 화면 / Collection 위 알림 | 비교형 대상(docs/03a §5)에 가까움 | 화면이 늘어남, 비교 전에 하나로 굳음 | 중간 |
| 저장 피드백: 상세 도착 시 한 줄 + 선 하나 그리기 | 조용하고 한 번만, 동작 줄이기에서는 정지 | 새로고침하면 `saved=1`로 다시 보일 수 있음 | 작음 |
| 중복 저장 방지: 저장 버튼의 ref 가드 | 같은 틱의 두 번 누름을 막음(상태 갱신 전) | 화면 단위 가드 | 작음 |
| 중복 저장 방지: 저장소에서 같은 글 거르기 | 어디서 호출해도 안전 | 같은 글을 일부러 두 번 쓰는 경우까지 막음 | 중간 |

## 결정과 이유
- `RecordsProvider`(메모리, 최신순)로 시작한다. 기록에는 `emotions: []`를 두어 "감정 없이 저장"이 모델에서 명시되게 하되, UI에는 감정 요소를 두지 않는다.
- 원문은 입력 그대로 저장한다(D-31). `isSubmittable`은 저장 버튼 활성 여부만 정한다.
- 저장 후 초안을 지우고 상세로 `replace`한다. 저장 피드백은 비교형 대상이므로 변형 하나(상세 도착 시 한 줄)만 만든다.
- 하루 여러 기록(D-14)은 날짜 규칙 없이 최신순으로 모두 보여 준다.
- 목록과 상세에 쓰는 날짜는 `2026년 11월 19일 21:05` 형식(기기 시간대, `Intl` 미사용).

## 진행 중 생긴 문제와 대응
- 두 번 누르기 테스트를 `Promise.all`로 만들면 `act()`가 겹쳐 이후 화면 상태가 어긋났다. 한 `act()` 안에서 두 번 누르는 방식으로 바꿨다(가드를 지우면 실패함을 변형 검사로 확인).
- 원문 `Text`에 `accessibilityLabel`을 달면 스크린 리더가 글 대신 라벨을 읽으므로, 라벨 대신 `testID`와 보이는 "원문" 제목을 썼다.
- 옛 "저장 기능은 다음 업데이트" 안내와 그 테스트는 동작이 바뀌어 제거했다(약화가 아니라 대체).

## 결과
구현·테스트는 PR 본문 참고. 실기기 느낌(피드백 선의 속도, 키보드)은 테스트로 확인할 수 없다.
