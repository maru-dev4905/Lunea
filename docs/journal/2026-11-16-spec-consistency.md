# 명세 불일치 정리(DOC-01): 이름은 고치고, 규칙은 질문으로 등록하기
- 날짜 / 관련: 2026-11-16, LUN-13, D-15, D-30~D-33

## 배경
데이터 모델 작업(PRIV-01, COL-01) 전에 문서끼리 어긋난 6곳을 정리해야 했습니다. Jira 수용 기준은 "해결했거나 `docs/10`에 질문으로 등록"입니다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 불일치를 전부 내가 정해서 고침 | 빠름 | 삭제·AI 해석·데이터 규칙은 제품 책임자의 결정을 내가 조용히 정하게 됨 |
| 전부 질문으로만 등록 | 안전 | 단순한 이름 충돌(`user_review`/`user_reviewed`)까지 미뤄져 데이터 모델 작업이 막힘 |
| **이름·구조는 고치고, 규칙은 질문으로 등록(채택)** | 막힌 곳만 풀고 결정은 사람에게 | 문서에 "D-xx 대기" 표시가 남음 |

## 결정과 이유
- **상태 이름(확정):** 저장되는 상태를 세 층으로 나눴습니다(`JournalEntry.status`, `AnalysisRun.status`, 후보의 `review_status`). `user_review(ed)`는 저장 상태가 아니라 화면 단계이고, `skipped`는 상태가 아니라 "후보를 모두 넘기고 확정하는 동작"이며, `discarded`는 초안 삭제라서 상태에서 뺐습니다. 기준 문서는 `docs/06`입니다.
- **AI 없이 저장(D-32, 제품 책임자가 허용):** `draft → saved` 경로를 `docs/02`에 추가하고 JRN-02의 "승인되면"을 지웠습니다.
- **근거 검증(D-33, 제품 책임자가 유사 일치를 우선 허용):** 저는 정확한 일치를 권했지만 제품 책임자가 유사 일치로 정했습니다. 알고리즘과 임계값은 AI-01/AI-03에서 합성 한국어 사례로 정하도록 남겼고, `docs/07`의 릴리스 차단 조건("조작된 인용")을 근거로 "모델의 풀어쓴 문장을 인용처럼 보여 주지 않고 사용자 원문의 일치 구간을 보여 준다"는 보호 장치를 제안으로만 적었습니다(아직 제품 책임자 확인 전).
- **삭제(D-30), 원문과 수정(D-31):** 처음에는 제품 책임자가 정할 일이라 질문으로 등록하고 제 권고안을 "미결정"으로 표시했습니다. 이후 제품 책임자가 권고안을 그대로 채택해 확정했습니다(완전 삭제·`deleted` 상태 없음, 수정은 이력으로 두고 본문이 바뀌면 재확인). D-33의 보호 장치(일치 구간을 원문 그대로 보여 줌)도 같이 채택했습니다.
- **확인 질문(D-15):** 권고안 없이 선택지만 정리했고 제품 책임자 결정이 남았습니다. 상태·API 없이 필드(`followUpQuestion`)만 있어서 "예약, 무시"로 표시했습니다.

## 진행 중 생긴 문제와 대응
- 일관성 검사(`scripts/check-spec-consistency.sh`)를 먼저 만들어 실패를 확인하고 문서를 고쳤습니다. 처음 만든 상태 이름 검사는 `02`의 상태 줄이 화살표를 포함한 한 덩어리라 이름을 하나도 뽑지 못해 "통과"로 나왔습니다. 비어서 통과하는 검사라 추출 방식을 고쳐 다시 실패를 확인했습니다.
- 검사 2건은 문서 본문의 백틱이 `bash -c` 문자열에서 명령으로 해석되어 실패했습니다. 문서가 아니라 검사의 결함이어서 `bash -c`를 쓰지 않도록 고쳤습니다.
- 문서 사본에 결함 8건을 넣어 모두 검출되는 것을 확인했습니다.
- CodeRabbit이 검사의 허점 2건을 짚었고 둘 다 사실이었습니다. 밑줄 없는 상태 이름(`archived`)과, 주 경로(`draft → … → saved`)에도 일치해서 직접 경로(`draft → saved`)를 지워도 통과하는 정규식이었습니다. 문서에 결함을 넣은 사본으로 놓치는 것을 먼저 확인하고, 백틱 경로의 모든 상태 이름을 추출·대조하도록 고치고 직접 경로를 정확히 검사하며 추출이 비면 실패하는 개수 가드를 넣었습니다.

검사 14개 통과, CI에도 연결했습니다. 제품 책임자가 남은 D-15를 정하면 데이터 모델 작업(PRIV-01, COL-01)에 들어갈 수 있습니다.
