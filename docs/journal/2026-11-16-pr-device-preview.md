# PR 실기기 미리보기(FND-05): 의존성이 늘어나는 비용을 재고 고르기
- 날짜 / 관련: 2026-11-16, LUN-12, ADR-0008(제품 책임자가 같은 날 Accepted), D-29

## 배경
인터랙션이 핵심이라 모든 UI PR을 실기기에서 보고 싶었습니다. Jira 수용 기준은 "PR을 열면 QR이 달리고 Expo Go로 실행됨"입니다.

## 고려한 선택지
| 선택지 | 장점 | 단점 | 비용 |
|---|---|---|---|
| A. `expo-updates` 직접 추가 + EAS Update + Expo Go | 설정이 저장소에 남음 | 패키지 +7 | 측정: node_modules +4 MB, JS 번들 동일 |
| B. CI에서 `eas update`가 자동 설치 | 저장소 변경 없음 | CI와 저장소가 달라지고 설정이 안 보임 | 0이지만 불투명 |
| C. 수동 로컬 확인 | 의존성 0 | 수용 기준 미달 | 매 PR 수작업 |
| D. 개발 빌드 + EAS Update | Expo Go 제약 없음 | 빌드·계정 비용 | 큼 |
| E. 직접 호스팅 | 통제 | 서버 운영 | 큼 |

## 결정과 이유
A. 가장 중요한 근거는 두 가지였습니다. (1) `eas update`는 `expo-updates`를 스스로 설치하므로 "의존성 없이"는 선택지가 아니었습니다(eas-cli 27.10.0 소스 확인). (2) 격리된 복사본에서 실제로 설치해 비용을 쟀더니 패키지 +7(전부 MIT, 설치 스크립트 없음), `node_modules` 726 → 730 MB, JS 번들 크기는 iOS·Android·Web 모두 동일했습니다. 제품 책임자가 장단점과 차이를 보고 선택하겠다고 해서 숫자로 비교했습니다. 운영 빌드의 OTA는 이 결정에 포함하지 않았습니다.

## 진행 중 생긴 문제와 대응
- `eas login`이 읽기 전용 권한으로 되어 `whoami`에 "limited to Viewer"가 떴습니다. 쓰기 권한으로 다시 로그인한 뒤 진행했습니다.
- `eas update:configure`가 `app.json`을 펼쳐 쓰고 `extra.router.asyncRoutes`를 추가했습니다. 해석된 설정에 기본값으로 이미 있어서 제거했고, 포맷도 원래대로 되돌려 diff를 `extra.eas`, `runtimeVersion`, `updates` 세 가지로 줄였습니다.
- 워크플로는 비밀 값을 다루므로 정책(`pull_request` 전용, 포크 제외, 최소 권한, 액션 SHA 고정, 브랜치명 미사용, 설치 후 토큰 노출)을 `scripts/check-workflows.sh`로 먼저 테스트로 만들고 구현했습니다. 정책을 일부러 깨뜨려 6건이 모두 잡히는 것을 확인했습니다.
- 컨테이너 이미지를 받아 `actionlint`를 돌리는 명령은 권한 분류기에 거부되어 실행하지 않았습니다. 대신 YAML 파싱과 정책 검사로 확인했습니다.
- 액션 버전은 문서 예시가 v8이었지만 최신은 9.0.2(Node 24 런타임 변경만)여서 9.0.2를 커밋 SHA로 고정했습니다.

## 결과
정책 검사 16개, 앱 검사, `expo export`가 통과합니다. 제품 책임자가 `EXPO_TOKEN`(조직 로봇 유저 토큰)을 저장하고 `Preview`를 다시 실행하자 PR에 QR 코멘트(android·ios, 런타임 0.1.0)가 달렸고 폰의 Expo Go에서 앱이 열렸습니다. CodeRabbit이 문서를 근거로 지적한 `runtimeVersion`과 Expo Go의 비호환 우려는 현재 구성에서는 해당하지 않음이 확인됐습니다. 재실행을 `Preview`가 아닌 `CI`에서 눌러 한 번 헛돈 것은 단순 조작 착오였습니다.
