# Supabase PoC(FND-04): 증명 가능한 것과 사람이 확인해야 하는 것 나누기
- 날짜 / 관련: 2026-11-13, LUN-11, ADR-0002, D-16, D-27, 결과: `docs/poc/FND-04-supabase.md`

## 배경
ADR-0002는 Supabase를 "PoC 통과 조건 6개"를 전제로 선택했습니다. 실제 데이터 없이, 가능한 한 자동 테스트로 증명하는 것이 목표였습니다.

## 고려한 선택지
| 선택지 | 장점 | 단점 | 비용 |
|---|---|---|---|
| RLS 테스트를 pgTAP(`supabase test db`)로 작성 | DB 안에서 역할·JWT를 직접 흉내 내 정확, 추가 의존성 없음 | SQL로 작성 | 낮음 |
| RLS 테스트를 앱 쪽(Jest + supabase-js)으로 작성 | 클라이언트 경로까지 확인 | 앱에 의존성 추가, 웹 저장소 문제(D-27)와 얽힘 | 높음 |
| Edge Function을 의존성 주입 구조로 분리해 Deno 단위 테스트 + 로컬 스택 통합 테스트 | DB 없이 빠른 검증과 실제 사용자 검증 둘 다 | Deno 도구 필요 | 중간 |

## 결정과 이유
pgTAP와 Deno 테스트를 택했습니다. 앱에 Supabase 클라이언트를 넣으면 웹 토큰 저장 방식(D-27, D-16)을 PoC에서 사실상 결정하게 되어, 세션 갱신의 기기 확인(조건 3)은 이 PR에서 제외하고 "사람 확인 필요"로 남겼습니다. 증명되지 않은 것을 통과로 적지 않는 것을 우선했습니다.

## 진행 중 생긴 문제와 대응
- Homebrew가 macOS 14에서 Deno 바이너리를 제공하지 않아 LLVM 소스 빌드를 시도하려 했습니다. 중단하고 `npx deno@2.9.6`로 대체했습니다(시스템 설치 없음, 버전 고정).
- 테스트 작성 실수 2건(데이터 변경 CTE는 최상위만 가능, anon 권한 회수 시 0행이 아니라 권한 오류)은 테스트를 고쳤고 구현은 바꾸지 않았습니다.
- 테스트가 실제로 결함을 잡는지 확인하려고 정책을 일부러 열어 보았습니다. 첫 변이(파생 행 소유 확인 제거)는 부모 테이블 RLS 때문에 걸러지지 않았고(이중 방어), 두 번째 변이(일기 정책 개방)는 6개가 실패했습니다.
- Edge Function의 `global.headers`에 소문자 `authorization`을 주면 인증 호출이 400이 되었습니다. 대문자 키로 해결했습니다.
- `docker info`가 Docker 꺼진 상태에서 응답 없이 멈춰 백그라운드로 남았습니다. 프로세스를 종료했습니다.

## 결과
조건 1, 2, 4, 6 통과, 3 부분 통과, 5 사람 확인 필요. 원격 프로젝트에는 아무것도 적용하지 않았습니다.
